# KPC-Toolbox (Python)

Python edition of the KPC-Toolbox for fitting Markovian Arrival Processes (MAPs)
and phase-type (PH) distributions to empirical traces via Kronecker Product
Composition (KPC).

This is a thin, standalone package: it does **not** reimplement any algorithm
that already ships in [`line-solver`](https://pypi.org/project/line-solver/).
Every fitting routine and numerical primitive is imported from `line_solver` and
re-exported under a flat namespace that mirrors the MATLAB KPC-Toolbox API
(`kpcfit_*`, `map_*`, `trace_*`, `aph_*`, `mmpp2_*`, `ctmc_*`/`dtmc_*`). On top of
that, this package adds the material the MATLAB toolbox ships that has no home in
`line-solver`: the example MAP library, runnable demos with bundled traces, a
handful of primitives `line-solver` lacks, and tests.

## Install

```bash
pip install kpc-toolbox        # pulls in line-solver, numpy, scipy
```

## Quick start

```python
import numpy as np
import kpctoolbox as k

# --- Phase-type fitting: match the first moments of a distribution ---
D0, D1 = k.map_hyperexp(1.0, 8.0, 0.6)          # a hyper-exponential, SCV=8
E = [float(k.map_moment(D0, D1, i)) for i in (1, 2, 3)]
options = k.kpcfit_ph_options(np.array(E))
fits = k.kpcfit_ph_auto(np.array(E), options)    # (PH, distance, params, method)
PH = fits[0][0]                                  # best fit, as (D0, D1)

# --- MAP fitting: fit autocorrelation of a trace ---
from kpctoolbox import demo
S = demo.load_trace("BCAUG89")                   # interarrival-time samples
trace = k.kpcfit_init(S)
MAP = k.kpcfit_auto(trace, OnlyAC=True)[0]       # best fit, as (D0, D1)
```

## What's here

- `kpctoolbox` — facade re-exporting the KPC engine and MAP/trace/PH primitives
  from `line-solver`.
- `kpctoolbox.examples` — the `maplib_*` example MAP library (Erlang,
  hyper-exponential, MMPP, circulant, saw-tooth, and the pre-fitted Bellcore
  Aug89 MAP).
- `kpctoolbox.demo` — runnable demos (`demo_kpcfit_bcaug89`, `demo_kpcfit_ph`)
  and trace loaders (`load_trace`), with the BCAUG89, DEC-PKT-1-UDP, and
  LIVEMAPS traces bundled as compressed `.npz`.
- `kpctoolbox._extras` — `krons`, `aph_from2moments` and `map2mmpp`, the three
  MATLAB primitives with no `line-solver` counterpart. Exported from the top
  level like everything else.

## Parity with the MATLAB toolbox

Values agree with `matlab/` to machine precision across MAP algebra and
statistics, the counting process, the composition kernels, the CTMC/DTMC
solvers, trace estimators, the `maplib_*` library, and the bundled traces
(bit-identical to the `.mat` originals). Three API differences are deliberate:

- `minpos`/`maxpos` return **0-based** positions here and 1-based positions in
  MATLAB. The elements selected are the same; only the index origin differs.
- `map_mmpp2` raises `ValueError` on an infeasible `(MEAN, SCV, SKEW, ACF1)`
  request; MATLAB raises `map_mmpp2:infeasible` for the same inputs.
- `version()` / `kpcfit_version()` report this package's version, which tracks
  the MATLAB toolbox, not the `line-solver` release underneath.

Two numerical differences remain, both benign and both understood:

- `kpcfit_ph_exact` can return more candidates than MATLAB. Prony's method on a
  moment set generated by a k-phase hyper-exponential is rank-deficient above
  order k, so the two languages' linear solvers land on different members of the
  same solution set. `kpcfit_ph_auto` still selects an exact fit either way.
- `trace_gamma` agrees with MATLAB to ~3e-7 rather than to machine precision.
  Both do a robust IRLS fit with 'fair' weights; the residual gap is MATLAB
  `nlinfit`'s internal robust-scale convention.

`line` spells the count-based MMPP(2) fitters `mmpp2_fitc*`; the MATLAB names
`mmpp2_fit_count*` are exported as aliases of the same functions.

Not ported from `matlab/`: the `kpcqbd/` QBD and MAP/MAP/1 queueing extension,
the parameter-space `psfit_*` fitters, `map_anfit`, and the optimizer
`*_outfun` callbacks.

## Entry points

| Task           | Functions                                        |
|----------------|--------------------------------------------------|
| MAP fitting    | `kpcfit_init` → `kpcfit_auto`                     |
| PH fitting     | `kpcfit_ph_options` → `kpcfit_ph_auto`           |

Note: keyword casing follows `line-solver`, which is not uniform. `kpcfit_auto`
keeps the MATLAB PascalCase (`OnlyAC`, `NumStates`, `MaxIterAC`, ...), while
`kpcfit_init` and `kpcfit_ph_options` take snake_case (`smooth=2`,
`max_num_states=8`, `verbose=False`).
